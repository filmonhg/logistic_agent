# Logistics Agent

A natural-language AI agent for shipping/logistics queries, built with [Strands Agents](https://strandsagents.com) on AWS.

Ask it things like *"Are there any routes from Mombasa to Kigali under $2400?"* and it queries a real database and answers in plain English.

```
┌──────────────┐    ┌──────────────────┐    ┌─────────────┐    ┌──────────────┐
│   You (Mac)  │───▶│  Strands Agent   │───▶│   Lambda    │───▶│  DynamoDB    │
│   REPL       │    │  (Claude/Qwen)   │    │ (boto3 SDK) │    │ Logistics... │
└──────────────┘    └──────────────────┘    └─────────────┘    └──────────────┘
                            ▲
                            │ LLM hosted in Bedrock (cloud)
                            │ OR on-prem via Tailscale (Ollama+Qwen)
```

This README is the complete build guide. Follow it top to bottom and you'll have a working agent in ~30 minutes.

## What you get

- **Interactive REPL** — chat with the agent, multi-turn memory, slash commands
- **Real backend** — DynamoDB table seeded with 8 sample logistics offers
- **AWS Lambda** — handles database queries, exposed as a Strands tool
- **Switchable LLM** — Bedrock Claude (cloud) or Ollama Qwen (on-prem) via one env var
- **Idempotent IaC** — every AWS resource scripted, safe to re-run any number of times
- **Pre-flight checks** — Python version, AWS creds, Bedrock access verified before deploy
- **One-command teardown** — leaves no AWS resources behind

## Phase 0 — One-time AWS account setup (Console)

Sign in as **root** only this once. After this, root stays locked away.

### 0.1 Lock down root

1. Sign in at https://console.aws.amazon.com as root
2. Top-right → your account name → **Security credentials**
3. Enable **MFA** on root using an authenticator app
4. Delete any root access keys listed

### 0.2 Create the IAM user for CLI work

1. **IAM** → **Users** → **Create user**
2. **User name:** `aigentic_user` (or any name you prefer)
3. Skip "Provide user access to the AWS Management Console"
4. Next → **Attach policies directly** → check these five:
   - `AmazonDynamoDBFullAccess`
   - `AWSLambda_FullAccess`
   - `IAMFullAccess`
   - `AmazonBedrockFullAccess`
   - `CloudWatchLogsFullAccess`
5. Next → **Create user**
6. Click the user → **Security credentials** tab → **Create access key**
7. **Use case:** Command Line Interface (CLI) → acknowledge → Next → Create
8. **Copy both** the Access Key ID and Secret Access Key — the secret shows once
9. Sign out of root

### 0.3 Submit the Anthropic use case form

This is the gate to using Claude on Bedrock. One-time per account.

1. Sign in as root
2. Top-right region → **US West (Oregon) us-west-2** ← critical, **not** us-west-1
3. Search **Bedrock** → left sidebar → **Model catalog**
4. Find **Claude Sonnet 4.6** → click
5. Click **Submit use case details**
6. Fill the form:
   - **Company:** your name or anything reasonable
   - **Website:** GitHub or LinkedIn URL
   - **Industry:** Logistics & Transportation (or Other)
   - **Intended users:** Internal employees
   - **Use case:** *"Internal development of a logistics assistant that helps carriers query a database of shipping offers. Prototype/learning project, no production deployment."*
   - **Outputs displayed to end users:** No
   - **Compliance / regulated data:** No
7. Submit. Typically approved in 1–5 minutes.
8. Sign out of root

## Phase 1 — Local Mac setup

### 1.1 Install AWS CLI v2 (current)

```bash
brew install awscli
```

If you have an old version installed via Amazon's PKG installer (showing `aws-cli/2.2.x` or older), remove it first:

```bash
sudo rm -f /usr/local/bin/aws
sudo rm -f /usr/local/bin/aws_completer
sudo rm -rf /usr/local/aws-cli
brew link --overwrite awscli
```

Verify:

```bash
which aws
aws --version
```

Must show:
- A path like `/usr/local/bin/aws` (Homebrew symlink) or `/opt/homebrew/bin/aws`
- Version `aws-cli/2.27.x` or newer

### 1.2 Install Python 3.12

```bash
brew install python@3.12
python3.12 --version          # must show Python 3.12.x
```

This is non-negotiable — `strands-agents` requires Python ≥ 3.10. macOS's default `python3` is often 3.9, which silently fails with confusing errors.

### 1.3 Configure AWS profile

```bash
aws configure --profile logistics-dev
# AWS Access Key ID:     <from Phase 0.2 step 8>
# AWS Secret Access Key: <from Phase 0.2 step 8>
# Default region:        us-west-2
# Default output:        json
```

Persist in shell:

```bash
echo 'export AWS_PROFILE=logistics-dev' >> ~/.zshrc
echo 'export AWS_REGION=us-west-2'       >> ~/.zshrc
source ~/.zshrc
```

Verify you're NOT root:

```bash
aws sts get-caller-identity
# Arn should end in :user/aigentic_user, NOT :root
```

### 1.4 Create the Python venv

**Use `python3.12` explicitly**:

```bash
cd ~/logistics-agent
python3.12 -m venv logistics-venv
source logistics-venv/bin/activate

python --version          # Python 3.12.x
which python              # inside logistics-venv/bin/
```

Your shell prompt should now show `(logistics-venv)`.

## Phase 4 — Lambda code

### `lambda/lambda_function.py`

```python
import json
import boto3
from decimal import Decimal
from boto3.dynamodb.conditions import Key

dynamodb = boto3.resource('dynamodb')
table = dynamodb.Table('LogisticsOffers')


class DecimalEncoder(json.JSONEncoder):
    def default(self, o):
        if isinstance(o, Decimal):
            return float(o)
        return super().default(o)


def lambda_handler(event, context):
    # Accept direct invoke, API Gateway proxy, or plain dict
    if 'body' in event and event['body']:
        params = json.loads(event['body']) if isinstance(event['body'], str) else event['body']
    elif event.get('queryStringParameters'):
        params = event['queryStringParameters']
    else:
        params = event

    origin = params.get('origin')
    destination = params.get('destination')
    max_rate = params.get('max_rate')

    try:
        if origin:
            response = table.query(
                IndexName='OriginIndex',
                KeyConditionExpression=Key('origin').eq(origin),
            )
        else:
            response = table.scan()

        items = response.get('Items', [])

        if destination:
            items = [i for i in items if i.get('destination', '').lower() == destination.lower()]
        if max_rate:
            items = [i for i in items if float(i.get('rate_usd', 0)) <= float(max_rate)]

        return {
            'statusCode': 200,
            'headers': {'Content-Type': 'application/json'},
            'body': json.dumps({'count': len(items), 'offers': items}, cls=DecimalEncoder),
        }
    except Exception as e:
        return {'statusCode': 500, 'body': json.dumps({'error': str(e)})}
```

## Phase 5 — Infrastructure deploy script

Creates DynamoDB table, IAM role, and Lambda function. **Idempotent** — safe to re-run any number of times.

### `infra/02_deploy_infra.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail

REGION="${AWS_REGION:-us-west-2}"
TABLE_NAME="LogisticsOffers"
ROLE_NAME="LogisticsLambdaRole"
LAMBDA_NAME="LogisticsQueryOffers"
PROJECT_DIR="$(cd "$(dirname "$0")/.." && pwd)"
LAMBDA_DIR="${PROJECT_DIR}/lambda"
ENV_FILE="${PROJECT_DIR}/.env"

ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
CALLER_ARN=$(aws sts get-caller-identity --query Arn --output text)

if [[ "$CALLER_ARN" == *":root" ]]; then
  echo "Refusing to deploy as root. Switch to an IAM user."
  exit 1
fi

echo "Account: $ACCOUNT_ID  Region: $REGION  As: $CALLER_ARN"

# 1. DynamoDB table
echo ""
echo "DynamoDB table: $TABLE_NAME"
if aws dynamodb describe-table --table-name "$TABLE_NAME" --region "$REGION" >/dev/null 2>&1; then
  echo "  Already exists, skipping."
else
  aws dynamodb create-table \
    --table-name "$TABLE_NAME" \
    --region "$REGION" \
    --attribute-definitions \
        AttributeName=offer_id,AttributeType=S \
        AttributeName=origin,AttributeType=S \
    --key-schema AttributeName=offer_id,KeyType=HASH \
    --global-secondary-indexes \
        "IndexName=OriginIndex,KeySchema=[{AttributeName=origin,KeyType=HASH}],Projection={ProjectionType=ALL},ProvisionedThroughput={ReadCapacityUnits=5,WriteCapacityUnits=5}" \
    --provisioned-throughput ReadCapacityUnits=5,WriteCapacityUnits=5 \
    >/dev/null
  echo "  Waiting for ACTIVE state..."
  aws dynamodb wait table-exists --table-name "$TABLE_NAME" --region "$REGION"
  echo "  Created."
fi

# 2. IAM role for Lambda
echo ""
echo "IAM role: $ROLE_NAME"
TRUST='{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"Service":"lambda.amazonaws.com"},"Action":"sts:AssumeRole"}]}'

if aws iam get-role --role-name "$ROLE_NAME" >/dev/null 2>&1; then
  echo "  Already exists."
else
  aws iam create-role \
    --role-name "$ROLE_NAME" \
    --assume-role-policy-document "$TRUST" \
    >/dev/null
  echo "  Created."
fi

aws iam attach-role-policy --role-name "$ROLE_NAME" \
  --policy-arn arn:aws:iam::aws:policy/service-role/AWSLambdaBasicExecutionRole
aws iam attach-role-policy --role-name "$ROLE_NAME" \
  --policy-arn arn:aws:iam::aws:policy/AmazonDynamoDBReadOnlyAccess
echo "  Policies attached."

echo "  Sleeping 12s for IAM propagation..."
sleep 12

# 3. Package Lambda
echo ""
echo "Packaging Lambda..."
cd "$LAMBDA_DIR"
rm -f function.zip
zip -q function.zip lambda_function.py
cd "$PROJECT_DIR"
echo "  Created lambda/function.zip"

# 4. Deploy / update Lambda
echo ""
echo "Lambda function: $LAMBDA_NAME"
ROLE_ARN="arn:aws:iam::${ACCOUNT_ID}:role/${ROLE_NAME}"

if aws lambda get-function --function-name "$LAMBDA_NAME" --region "$REGION" >/dev/null 2>&1; then
  echo "  Updating code..."
  aws lambda update-function-code \
    --function-name "$LAMBDA_NAME" \
    --region "$REGION" \
    --zip-file "fileb://${LAMBDA_DIR}/function.zip" \
    >/dev/null
  echo "  Updated."
else
  echo "  Creating..."
  aws lambda create-function \
    --function-name "$LAMBDA_NAME" \
    --region "$REGION" \
    --runtime python3.11 \
    --role "$ROLE_ARN" \
    --handler lambda_function.lambda_handler \
    --zip-file "fileb://${LAMBDA_DIR}/function.zip" \
    --timeout 10 \
    >/dev/null
  echo "  Created."
fi

# 5. Write .env
cat > "$ENV_FILE" <<EOF
# Auto-generated by 02_deploy_infra.sh
export AWS_REGION=${REGION}
export AWS_PROFILE=${AWS_PROFILE:-logistics-dev}
export DDB_TABLE=${TABLE_NAME}
export LAMBDA_NAME=${LAMBDA_NAME}
export BEDROCK_MODEL_ID=us.anthropic.claude-sonnet-4-6
export LLM_PROVIDER=bedrock
EOF

echo ""
echo "Infrastructure deployed."
echo "  Config written to: $ENV_FILE"
echo ""
echo "Next:"
echo "  source .env"
echo "  python infra/03_seed_data.py"
echo "  ./infra/04_verify.sh"
```

## Phase 8 — The agent (interactive REPL)

Supports both Bedrock (cloud) and Ollama (on-prem). Switch via `LLM_PROVIDER` env var, or use `/switch` inside the REPL.

### `agent/agent_direct.py`

```python
"""Strands agent with switchable LLM provider - Bedrock or Ollama."""
import json
import os
import boto3
from strands import Agent, tool

REGION = os.environ.get("AWS_REGION", "us-west-2")
LAMBDA_NAME = os.environ.get("LAMBDA_NAME", "LogisticsQueryOffers")

lambda_client = boto3.client("lambda", region_name=REGION)


@tool
def find_logistics_offers(origin: str = None, destination: str = None, max_rate: float = None) -> str:
    """
    Find available shipping/logistics offers between cities.

    Args:
        origin: The origin city (e.g., 'Mombasa', 'Nairobi'). Optional.
        destination: The destination city (e.g., 'Kigali', 'Kampala'). Optional.
        max_rate: Maximum acceptable rate in USD. Optional.

    Returns:
        JSON string listing matching offers with shipper, rate, and transit days.
    """
    payload = {}
    if origin: payload["origin"] = origin
    if destination: payload["destination"] = destination
    if max_rate: payload["max_rate"] = max_rate

    response = lambda_client.invoke(
        FunctionName=LAMBDA_NAME,
        Payload=json.dumps(payload),
    )
    result = json.loads(response["Payload"].read())
    return result.get("body", "{}")


SYSTEM_PROMPT = (
    "You are a logistics assistant for carriers. "
    "ALWAYS call find_logistics_offers before answering any question about routes, rates, or shippers - "
    "do not answer from memory. "
    "Pass numeric values as numbers, not strings. "
    "Present results clearly with origin, destination, shipper, rate, and transit days. "
    "If a user gives partial info, still try the lookup and let them refine. "
    "Be concise and friendly."
)


def make_model():
    """Build the model based on LLM_PROVIDER env var."""
    provider = os.environ.get("LLM_PROVIDER", "bedrock").lower()
    if provider == "ollama":
        from strands.models.ollama import OllamaModel
        host = os.environ.get("OLLAMA_HOST", "http://localhost:11434")
        model_id = os.environ.get("OLLAMA_MODEL", "qwen2.5:7b")
        print(f"Using Ollama: {model_id} @ {host}")
        return OllamaModel(host=host, model_id=model_id, temperature=0.3)
    elif provider == "bedrock":
        from strands.models import BedrockModel
        model_id = os.environ.get("BEDROCK_MODEL_ID", "us.anthropic.claude-sonnet-4-6")
        print(f"Using Bedrock: {model_id} @ {REGION}")
        return BedrockModel(model_id=model_id, region_name=REGION)
    else:
        raise ValueError(f"Unknown LLM_PROVIDER: {provider} (use 'bedrock' or 'ollama')")


def banner():
    print("=" * 64)
    print("  Logistics Agent - Interactive Mode")
    print(f"  Provider: {os.environ.get('LLM_PROVIDER', 'bedrock')}")
    print(f"  Lambda:   {LAMBDA_NAME}  ({REGION})")
    print("=" * 64)
    print("Commands:  /help   /clear   /history   /switch   /exit  (Ctrl+D)")
    print("-" * 64)


def new_agent(model):
    return Agent(model=model, tools=[find_logistics_offers], system_prompt=SYSTEM_PROMPT)


def main():
    model = make_model()
    agent = new_agent(model)
    banner()

    turn = 0
    while True:
        try:
            user_input = input("\n> ").strip()
        except (EOFError, KeyboardInterrupt):
            print("\nBye")
            break

        if not user_input:
            continue

        if user_input.startswith("/"):
            cmd = user_input.lower()
            if cmd in ("/exit", "/quit", "/q"):
                print("Bye")
                break
            if cmd in ("/help", "/h", "/?"):
                print("Commands:")
                print("  /help     show this help")
                print("  /clear    reset the conversation")
                print("  /history  show how many turns so far")
                print("  /switch   toggle bedrock <-> ollama")
                print("  /exit     leave (or Ctrl+D)")
                continue
            if cmd == "/clear":
                agent = new_agent(model)
                turn = 0
                print("Conversation cleared.")
                continue
            if cmd == "/history":
                print(f"Turns so far: {turn}")
                continue
            if cmd == "/switch":
                current = os.environ.get("LLM_PROVIDER", "bedrock").lower()
                new = "ollama" if current == "bedrock" else "bedrock"
                os.environ["LLM_PROVIDER"] = new
                try:
                    model = make_model()
                    agent = new_agent(model)
                    turn = 0
                    print(f"Switched to {new}. Conversation cleared.")
                except Exception as e:
                    os.environ["LLM_PROVIDER"] = current
                    print(f"Switch failed: {e}")
                continue
            print(f"Unknown command: {user_input}  (try /help)")
            continue

        turn += 1
        try:
            agent(user_input)
        except Exception as e:
            print(f"\nError: {e}")
            print("   (Conversation continues - try again or /clear)")


if __name__ == "__main__":
    main()
```

## Switching the LLM: Bedrock ↔ Ollama (Qwen on-prem)

The agent can run against either Claude on Bedrock (the default) or a Qwen model hosted on your own server via Ollama. Same code, same tools, same data — only the LLM changes.

### Why you might want Ollama

- **Free** — no Bedrock token charges
- **Private** — prompts never leave your network
- **No cloud LLM dependency** — useful for offline / air-gapped contexts

### One-time server setup

If your Ollama server is on-prem and you access it via Tailscale (recommended for security):

```bash
# On the Ollama server, make it bind to 0.0.0.0 so non-localhost can reach it
sudo systemctl edit ollama.service
```

Add:
```ini
[Service]
Environment="OLLAMA_HOST=0.0.0.0:11434"
Environment="OLLAMA_KEEP_ALIVE=24h"
```

Then:
```bash
sudo systemctl daemon-reload
sudo systemctl restart ollama

# If using UFW, allow Tailscale interface
sudo ufw allow in on tailscale0

# Pull a tool-capable Qwen model
ollama pull qwen2.5:14b
```

### Find your server on the tailnet

On your Mac:

```bash
tailscale status        # shows your servers; note the MagicDNS name or 100.x.y.z IP

# Verify reachable
curl http://<server>:11434/api/tags
```

### Switch the agent

Two ways:

**Option 1: Edit `.env` and restart**

## How it works

### Strands' core idea

Strands is a Python framework where you:
1. Define **tools** — regular Python functions decorated with `@tool`
2. Pick a **model** — Bedrock, Ollama, OpenAI, Anthropic, Gemini, etc.
3. Wrap them in an `Agent` — Strands handles the LLM ↔ tool conversation loop

The agent reads the user's question, decides which tool to call (if any), executes it, reads the result, and produces a natural-language answer.

### Why a Lambda for the tool?

1. **Separation of concerns** — agent code stays clean; DB query logic lives in its own deployable unit
2. **Future-proofing** — when you later expose this same backend to a web app or mobile client (via API Gateway), the Lambda is already there
3. **Security boundary** — the agent only has permission to invoke the Lambda, not to read DynamoDB directly

For pure local dev you *could* skip the Lambda and have the `@tool` function read DynamoDB directly. The Lambda layer is intentional architectural prep work.

### Tokens

LLMs measure everything in **tokens** — small chunks of text, usually a few characters each. Pricing, speed, context windows, and limits are all in tokens. For English, 1 token ≈ ¾ of a word.

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `Could not find a version that satisfies the requirement strands-agents` | Python < 3.10 | Recreate venv with `python3.12` |
| `aws: command not found` | Homebrew not linked | `brew link --overwrite awscli` |
| `Invalid choice: bedrock-runtime` | AWS CLI too old | `brew upgrade awscli` (need 2.13+) |
| `ResourceNotFoundException: use case details` | Anthropic form not submitted | Console → Bedrock → submit form (Phase 0.3) |
| `AccessDeniedException` on Bedrock | IAM permission missing | Attach `AmazonBedrockFullAccess` to your user |
| `ValidationException` on Claude model ID | Used bare ID | Use `us.anthropic.claude-sonnet-4-6` (with `us.` prefix) |
| `Unable to locate credentials` | Profile not exported | `export AWS_PROFILE=logistics-dev` |
| Lambda creation fails: role doesn't exist | IAM not propagated yet | Script sleeps 12s; if still fails, re-run |
| Ollama: `Connection refused` from Mac | Ollama bound to 127.0.0.1 only | Set `OLLAMA_HOST=0.0.0.0:11434` on server, restart |
| Ollama: model not found | Wrong tag | `ollama pull qwen2.5:14b` on the server |
| Qwen ignores tools, answers from memory | Weaker tool-calling | Tighten system prompt or use larger Qwen variant |

## Architecture decisions worth knowing

- **Region us-west-2 (Oregon)** — Claude on Bedrock is **not** available in us-west-1 (N. California). us-west-2 is the canonical Bedrock region.
- **`us.` inference profile prefix** — `us.anthropic.claude-sonnet-4-6` uses cross-region inference. The bare `anthropic.claude-sonnet-4-6` ID doesn't work for on-demand throughput.
- **Bash for IaC** — not because it's the best (SAM/CDK/Terraform are), but because for ~5 resources, bash is honest, transparent, and has zero learning curve. Graduate to SAM when complexity demands it.
- **No API Gateway in v1** — the agent uses `boto3.lambda.invoke()` directly. Cleaner for local dev; add API Gateway when you have non-AWS clients.
- **IAM user, never root** — root is locked down with MFA after Phase 0. All daily work uses the `aigentic_user` IAM user with scoped permissions.
- **Anthropic use case form** — required by Anthropic (not AWS) before invoking Claude on Bedrock for the first time. One-time per AWS account.
